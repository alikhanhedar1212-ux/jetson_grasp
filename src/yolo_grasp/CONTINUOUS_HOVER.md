# 连续接近物块

> **关于本仓库**：本文记录抓取/放置腿在现场的实测过程、守卫阈值与异常处置，是完整开发项目的笔记。本仓库只包含完整抓放流程需要的文件，文中提到的标定、审计与测试入口不在仓库内；路径 `/path/to/this/repo` 请替换成你的实际路径，`cd src` 指本仓库的应用目录。

在项目根目录运行。先完成急停恢复，固定点张爪结束后在旧控制终端输入 `quit`，再启动悬停。

```bash
python src/yolo_grasp/hover_red_block.py --channel can1 \
  --clearance-mm 10 --max-joint-delta-deg 90 --max-travel-mm 200 \
  --device cpu --imgsz 320 --min-available-mb 1200
```

程序仍需在终端输入一次 `go` 才会向识别目标移动。空格 / Esc / Ctrl+C 停止。开始运动前重新确认目标，运动中持续检测红块；目标变化时停稳，再从当前位置重新定位和规划。详细阈值与失败处理见下文“红块移动后停稳重规划”。

规划点用于生成带起止速度渐变的时间轨迹，约 50 Hz 更新普通 CAN/J 目标，抓取接近与抬升的目标关节速度上限为 5°/s，SDK 速度仍为 3%。中间点不再等待模式确认及停稳；终点必须用新反馈确认关节误差 ≤0.2°、停止状态持续 0.5 秒，再复核法兰误差 ≤3 mm / 1°。普通 J 模式的实际平滑性仍需现场验证，不使用无平滑的 JS/MIT 模式。

执行保留关节限位、反馈新鲜度、使能和 CAN/J 模式监控。反馈与目标差超过 0.8°、实际关节超出最近 0.25 秒目标包络 0.3°、调度延迟超过 100 ms 会停止；不会追赶补发积压目标。发送时间轻微延迟会延长总时长。

高度指临时 TCP 相对识别表面点沿基座 +Z 的偏移，不是实测指尖间隙。TCP 距离 2026-09-11 依次试过 90 / 80 / 60 mm：60 mm 时现场观察到夹爪落到物块下方，因此回到用户实测的 80 mm 复测。方向仍假设为法兰局部 +Z，尚未完成完整工具标定；手眼外参也是候选值，物块检测中心的深度未必代表顶面。程序最终打印反馈换算的临时 TCP 与物块的 XYZ 差，不能替代真实工具标定。

2026-09-11 保存的观测（`runs/hover_go_20260911_085621`）中，旧运行只完成索引 0–18 后停止，没有完成整个悬停，不能把当时机械臂的位置当作最终 30 mm 悬停位置。

用户已允许本次使用 90° / 200 mm 包络，以上命令显式传入，程序不会自动扩大限制。此前使用同一观测及旧的 90 mm TCP 离线重算 10 mm 目标：最大关节变化约 67.6°、法兰位移约 130.3 mm；路径 301 点，连续运动预计约 63.4 秒，终点 TCP 相对识别点为 `(0, 0, +10) mm`。实际运行必须重新识别、重新规划，旧记录只用于离线核对。

离线测试只验证计算、调度和停止逻辑；尚未通过本次改动后的真机连续运动验证。距离更新不能代替法兰局部 +Z 方向、横向偏移和手眼外参的完整标定。

## 正常完成后的保持

终点关节及法兰复核成功后进入无限时保持：不再发送运动目标，不自动失能或请求急停。CAN 反馈、使能、模式和位置偏移仍继续监控；真实故障和手动急停仍会停止。

到位后关闭相机窗口或相机预览异常只影响显示，不中断机械臂保持。运动完成前的相机窗口关闭仍触发停止。到位后终端 `quit` / Ctrl+D / EOF 正常退出监控，机械臂继续保持使能和最后位置；空格 / Esc / Ctrl+C，以及窗口 Q / Esc / 空格仍为明确的急停操作。`home` 仅在正常未锁定会话中回到位置，且会**先回固定抓取点、再回初始位置**（见下节）。

日志新增 `hold_started`、`hold_exit`、`hold_preview_unavailable`。急停发生前记录 `emergency_stop_requested.reason`，便于区分真实故障、运动到位超时和用户停止；没有看到 `hover_reached` / `hold_started` 时不能认定运动已经正常完成。

## 固定点识别失败后重试

无红块、多个红块或深度校验不通过时，程序不会发出接近目标，也不会仅因这些识别结果请求急停。机械臂保持固定点并继续监控 CAN / 关节位置和检测红块，窗口继续显示检测画面和失败原因。

抓取全程默认保持相机窗口和 YOLO 检测，包括规划、接近、闭爪及抬升。`--no-window` 仅关闭显示，不关闭检测。初始识别/规划失败等待人工 `retry` 时也继续检测。

### 红块移动后停稳重规划

输入一次 `go` 后，接近过程使用 **5°/s** 关节目标速度和原有 50 Hz 指令循环。按相机 global/system 时间戳查询对应的 CAN 法兰位姿历史（平移插值和旋转 Slerp），计算物块基座坐标，避免将相机自身运动误判为物块移动。拒绝硬件时钟域、超过 1 秒的观测、超过 100 ms 的位姿历史间隔和外推；CAN 分帧时间差仍不得超过 50 ms。

连续两张不同检测帧的基座坐标相对本段目标变化超过 **20 mm**（`--target-move-mm`，5–50）时，丢弃旧轨迹剩余部分，以新鲜关节反馈发送正常 CAN/J 位置保持指令，并等待新反馈确认至少 **0.5 秒停稳**。目标丢失、多目标、无效深度或无法同步时也先停止接近。保持/反馈失败仍进入原有急停处理，不自动复位或重新使能。

停稳后只接受停稳之后拍摄的图像：至少三帧、跨越 0.3 秒、基座坐标相对首帧在 5 mm 内。15 秒内没有稳定目标则结束本次抓取，不盲目搜索。使用新目标与停稳后的实际法兰/关节位置重新求解路径，不返回固定观察点；保留原有 IK、单步、累计关节限位，并限制新目标仍在最初的法兰位移包络内。规划期间持续监控 CAN 和停止键，规划后再次获取新观测，防止规划期间物块又移动。最多自动重规划五次（`--max-replans`），失败或超限停止，不执行旧轨迹。

到位后再次观察稳定目标，确认没有移动才允许进入闭爪。闭爪与抬升仍运行检测，但已经进入接触阶段，不再追赶被夹爪带动的物块；现有夹爪反馈和抬升检查继续生效。该功能是停稳后重规划，不是连续视觉伺服，也不包含动态障碍物避让。新增日志包括 `tracking_interrupt`、`tracking_hold_requested`、`tracking_hold_settled`、`tracking_target_stable`、`tracking_replan`、`tracking_pregrasp_verified`；最终采用的诊断写入 `final_tracking_diagnostic.json`。

单独抓取和 `pick_and_place.py` 组合入口均默认启用，组合入口可传相同的两个跟踪参数。实际停止距离和运动中的时间同步仍需在设备上验证，离线测试不能代替这些测量。

### 检测、规划与 CAN 控制的进程隔离

2026-09-16 的 `hover_go_20260916_161020` 在输入 `go` 前发生 CAN 接收积压，反馈逐步接近 250 ms 上限。抓取入口现使用 `spawn` 启动两个计算子进程，避免与控制线程争用同一个 Python GIL，也不继承 CAN 套接字或 CUDA 状态：

- **视觉进程**独占相机、YOLO、深度校验与点云。只回传带原始拍摄时间戳的检测点、元数据和标注图；控制进程不加载模型、不接收张量和整帧点云。单槽共享内存覆盖旧结果，读取不等待锁，避免积压视频帧；检测最高 10 Hz，窗口绘制最高 10 Hz，停止键仍逐次轮询。需要保存原始观测时按准确帧标识请求子进程归档，找不到该帧就报错，不换成另一帧。
- **规划进程**接收纯数值请求，完成初次规划、中途重规划和抬升路径。控制进程等结果期间继续检查 CAN 和停止键；请求编号防止使用旧结果，规划失败不会执行轨迹。超时、控制异常或手动停止会终止并回收计算任务。
- 计算子进程的数值计算线程数限制为 1，运行优先级降低；可用 CPU 至少四个时，分别绑定到第 3、第 4 个可用 CPU，为控制与接收留出其余 CPU。
- CAN 接收按最多 256 帧或 2 ms 分批清理缓冲区，每种报文保留批次最新帧；保留内核原始时间戳，仍按 250 ms 拒绝陈旧反馈，不用放宽阈值掩盖积压。

`compute_workers_started` 记录各进程 PID，`runtime_latency` 每秒记录当前阶段的主循环最大间隔、检测年龄、采集/推理时间和 CAN 接收延迟。进程退出和相机异常继续进入原有停止处理，结束会话时回收子进程。

可先在机械臂停稳时运行只读并发负载检查（相机不能被其它程序占用）：

```bash
python src/yolo_grasp/check_tracking_load.py --channel can1 --device cpu --imgsz 320 --seconds 15
```

该脚本只读取相机/CAN、重复计算已有 `diagnostic.json` 的路径，不创建机械臂控制器，不使能、不复位、不发送运动命令。默认选择最近有效诊断，也可用 `--diagnostic 路径` 指定。检测年龄超过 1 秒、CAN 反馈超过 250 ms 或主循环间隔超过 100 ms 会失败；统计保存到 `runs/tracking_load_*.json`。通过只读检查不代表已经验证真实停止距离或运动安全性。

2026-09-16 16:38 的现场只读检查通过，记录为 `runs/tracking_load_20260916_163837.json`。CPU / imgsz 320 / 无窗口配置，约 12 秒内完成三次完整路径计算并取得 66 张不同检测帧；CAN 反馈年龄最大 32.54 ms、主循环间隔最大 14.28 ms、视觉结果年龄最大 424.95 ms。该结果验证了停稳时的并发负载，不包含显示窗口开销或实际运动测试。

在终端输入 `retry` 回车重新采集识别，或输入 `quit` 正常退出并保持使能；Ctrl+D / EOF 也正常退出。输入 `go` 不能绕过无效识别。重新识别成功后才规划路径，并另行等待 `go`。空格 / Esc / Ctrl+C 及窗口停止键仍请求急停；真实 CAN 故障、位置变化、相机线程故障仍按故障处理。

`observation_rejected` 日志保存失败原因、检测数量（如适用）、像素位置及可获取的中心原始深度与分类；非有限深度记为 null，并以 `center_depth_category=nonfinite` 标识。重试会清除旧检测，新的目标有效期从新观测采集时刻计算。深度阈值和中心空洞拒绝规则保持不变。

TCP 距离 2026-09-11 依次试过 90 → 80 → 60 mm，60 mm 时夹爪落到物块下方，故回到 80 mm。上述 90 mm 离线结果仅为历史记录；运行时按当前代码里的 80 mm 重新识别和规划。距离每变 20 mm，法兰在同样的“表面上 X mm”目标下沿工具轴移动 20 mm——在这个姿态下基座系约 **+16 mm 前方、−12 mm 下方**（60 mm 相对 80 mm）；抓取姿态本身不变，也不会补偿未标定的横向 TCP 偏移。现场观察到手臂整体偏前/偏低时，优先怀疑这个距离与方向假设，而不是规划。

规划拒绝（包括位移/关节变化超限、IK 不可解、路径步长不满足）也进入固定点 `retry` / `quit` 等待，不因规划拒绝请求急停。默认及显式上限不变，`go` 不能绕过拒绝。CAN 故障、位置变化、手动停止仍按故障/急停处理。仅离线规划的 ValueError 在此恢复，运动执行错误不会进入重试。

每次有效识别后的规划保存到 `attempt_001`、`attempt_002` 等目录，包含 observation、detection.png、diagnostic.json；根目录 diagnostic.json 保留最新诊断。`planning_rejected` / `plan` 事件包含 attempt_dir，避免重试覆盖旧观测或因目录已存在而中断。

用户随后允许将本次法兰总位移上限扩大到 200 mm，运行命令使用 `--max-travel-mm 200`。程序默认仍为 150 mm，可配置最大值现为 200 mm；原 160 mm 记录属于历史设置。J6/其他关节变化上限仍由 `--max-joint-delta-deg 90` 限制。已经运行的进程不会自动载入新参数，需要退出并重新启动。

## 固定点等待不再因自发偏移急停

机械臂到位后会在约 12–16 秒静止后自发偏移 0.3–0.4°（2026-09-10 的 `runs/hold_check_20260910_153053`：16.0 秒静止后单帧跳到 0.339°；2026-09-11 两次悬停运行分别在 12.0 秒和 22.0 秒出现同样量级、同方向的跳变，法兰约 1.8 mm / 0.4°）。原来的「瞬时偏离 0.2–0.3° 即急停」使任何超过约 12 秒的停留（例如识别失败后等 `retry`）都必然以电子急停结束，2026-09-11 10:00 的运行就是这样停止的。

现在等待期间改用单独的可配置上限 `--hold-tolerance-deg`（默认 0.8°，可用 0.2–10°）：识别等待、规划重试等待、`go` 确认窗口以及连续运动起步时的偏差都用它判定，上面的自发偏移不再请求急停。运动中的包络（0.3°）、反馈落后/下一目标 0.8°、终点 0.2° 停稳和法兰 3 mm / 1° 复核都不变。上限高于 0.8° 时终端会提示：若起步瞬间偏差仍超过 0.8°，连续运动会拒绝起步而不是自动纠正。超限停止的日志文案也随之带出实际阈值（「偏离固定点超过0.8°」）。

这只放宽了「停在原地」的判定，没有改变任何运动目标、速度或到位判据；机械臂自身的故障、失能、模式丢失和反馈超时仍立即急停。偏移量是否随时间累积（多次自发偏移）尚未实测，若现场看到累积，用 `--hold-tolerance-deg` 放宽并按提示确认起步偏差。

## 单帧反馈毛刺不再直接停机，并记录双通道原始帧

关节帧 `0x2A5–0x2A7` 会偶发单帧错值：09-10 审计用电机帧 `0x251–0x256` 对照过 J4「恰好 0.000°」而真值约 −0.39°；2026-09-11 10:32 的运行里，J2 在 19 ms 内从 60.653° 变成 60.284°（−0.369°，其余五轴完全不动，该值约等于 1 秒前经过的旧值），越出运动包络 0.05–0.1° 即请求电子急停。同类单帧毛刺此前也表现为停驻期 0.3–0.4° 的「自发偏移」。

现在位置守卫改为**持续越界才停**：连续 `GUARD_PERSIST_SAMPLES = 3` 帧（约 35–50 ms）越界才请求电子急停，单帧毛刺只记录不停机；同时保留**更宽的硬界限** `GUARD_HARD_MARGIN_DEG = 1.5°`（包络之外）和运动跟随误差硬界限 `FOLLOW_HARD_DEG = 2.0°`，单帧超过它们仍然立即急停。跟随误差 0.8° 的判定同样改为连续 3 个目标越界才停。真实的跟随误差、失能、模式丢失、反馈过期都不受影响。

每次被忽略的毛刺会打印一行提示，并把该时刻前后约 2 秒的**双通道原始帧**写入运行目录的 `guard_strike_NN.jsonl`；任何停止（含急停）都会把同样的缓冲区写成 `can_trace_abort.jsonl`。缓冲区由独立的只收不发 SocketCAN 监听线程维护（`grasp/can_trace.py`），只订阅 `0x2A5–0x2A7` 与 `0x251–0x256`，不发送任何帧、也不参与控制；监听启动失败只打印提示并继续，不影响运动。用这些文件可以直接判断毛刺是真位移（两条通道同时变）还是反馈假象（只有关节帧变）。快照的复制和落盘在**工作线程**里完成（2026-09-18 10:17 那次单帧越界 +0.109° 时，同步 dump 3608 帧/428 KB 让主循环晚了 109 ms，反而触发「连续目标调度延迟超过 100 ms」的电子急停；现在钩子只记事件和启动线程，退出前统一 join）。

守卫还必须忽略两种**已知不可信**的读数，否则会误停：

1. **零区锁死**：`|关节帧读数| ≤ 0.35°` 时关节帧可能直接报 `0.000`，而电机帧显示真值（2026-09-11 11:30 的运行：关节帧 `0.000`，电机帧 `−0.286°`、转速 0，偏差算成 0.301° 刚好越过包络，连停 3 帧触发急停）。这类读数在偏差 ≤0.7° 时一律不计入守卫。
2. **量化噪声**：1 个计数就是 0.001°，越界不足 0.05° 的样本不计入守卫（否则会拿 0.001–0.005° 的跟随抖动停机）。

硬界限（包络外 1.5°、跟随误差 2.0°）不受这两条影响，仍然单帧立即停。

## 放置腿：识别蓝垫上的黑色框（`place_on_frame.py`）

2026-09-14 更新：物块尺寸为 30×20×30 mm，无偏航朝向要求。放置入口默认 TCP
停在识别黑框平面上方 55 mm（`--clearance-mm` 默认 55：2026-09-14 由 45 增加 5 mm，
2026-09-18 再由 50 增加 5 mm，完整流程的 `--place-clearance-mm` 同步）。放置目标默认叠加基座系偏移
`--target-offset-mm 5 5 0`，即从黑框中心沿基座 X、Y 正方向各补偿 5 mm；完整流程
默认沿用该偏移，可用 `--place-target-offset-mm` 覆盖。工具轴尽量沿基座 −Z（**实际能达到的最小倾斜由
J5 的机械行程决定，见下节**）。路径分两段，都在 `go` 前规划好：先保持当前姿态
把 TCP 平移到黑框正上方（过渡点高度取当前 TCP 高度与最终 TCP 高度加 70 mm

### 为什么工具轴不在高处完成转向（2026-09-14 的 IK 停机）

`runs/place_frame_20260914_105052` 在预移动完成后规划时停机：
`IK 拒绝：残差超限：位置0.213113 mm，姿态0.310174°；无运动`（J5 被顶到
88.9°，限位 ±89°）。离线按同一帧复算确认这不是数值噪声，而是**几何不可行**：
黑框落在离基座约 0.40 m 处，这个位置要把工具轴保持竖直向下，J5 会随 TCP
升高而增大；实测**只到目标上方约 20 mm 还可解，再高就没有满足 ±89° 的解**。
旧规划要求"先到正上方 113 mm 处完成转向"，即在 113 mm 高度上给出竖直姿态，
于是 IK 只能给出被 J5 限位截断的近似解，残差 0.31° 触发 `solve_target` 的
0.2° 判据，异常一路抛到最外层，按故障停机（机械臂停住并请求急停）。

现在 `vertical_paths()` 先按同一组关节限位**搜出这个可解高度**（`tool_down_reach`，
1 mm 步长，从最终目标往上逐点解 IK，失败处即边界），然后：

1. 平移段保持当前姿态到正上方过渡点 —— 姿态不变，移动的是 TCP 位置；
2. 下降段在这一段里把工具轴转到竖直，转到位的最高点就是搜出来的可解高度；
3. 最后一段是工具轴已经竖直、TCP 只沿基座 −Z 下去的垂直下沉，终点姿态与落点
   与旧规划完全一致（黑框上方 30 mm、工具轴竖直；2026-09-14 起默认先改为上方 40 mm、当晚再上调到 45 mm）。

同一帧实测：可解高度 20 mm，路径 451 点、最大单步 0.49°，末端 151 点是竖直
下沉（XY 漂移 0.1 mm，法兰误差 ~1e-11），整个路径在真实关节限位下全部可解。
代价是工具轴（以及爪里的物块）在下降段才转 53°，落点朝向要按物块姿态考虑；
下降段因此变长（约 78 秒 @2°/1.5°），需要更快时调 `--final-speed-deg-s`。
预移动后的**规划拒绝不再按故障停机**：打印原因并进入 `retry` / `quit` 等待
（与识别失败同一套策略，空格/Esc/Ctrl+C 仍是急停），日志新增
`planning_rejected` / `planning_retry` / `planning_exit`。

### 终端输入可编辑（2026-09-14 第二次更新的起因）

操作员在 `输入 shift 回车` 那一步打错字，发现**退格删不掉**。原因是旧的读键
循环对退格只做了 `pending[:-1]`，**没有把屏幕上的字符擦掉**，所以字看起来还在；
而 Delete 键发送的是 `ESC [ 3 ~`，旧循环按第一个字节 `ESC` 处理，会直接请求急停。
现在**两条腿所有需要输入单词的地方**都共用同一个模块
`grasp/terminal_input.py` 的 `type_word()`：抓取腿的 `retry` / `go` /
`home` / `quit`（`grasp/hover_observation.py`、`hover_red_block.py`）与放置腿的
`retry` / `go` / `shift` / `quit` / `home`（`place_on_frame.py`）行为完全一致。
（2026-09-14 晚：操作员在抓取腿的 `retry` 提示里再次遇到删不掉，就是因为那几处
还在用旧循环；现在它们都改成调用同一个函数，只改按键处理，运动与守卫逻辑未动。）

1. Backspace（`0x7F`/`0x08`）和 Delete（`ESC [ 3 ~`）都真正擦掉屏幕上最后一个字符；
2. Ctrl+U 清空整行；
3. 方向键、Delete、Home/End 等**转义序列整体吃掉并忽略**，不会误触发急停，
   也不会漏进输入的单词里；**单独按 Esc 仍然是急停**（读键后 30 ms 内没有后续
   字节即判定为单独的 Esc）；
4. 输错单词回车后提示里带出了可用的编辑键，不再只提示"请输入 X 或 quit"。

### 预移动（蓝垫在固定点看不全时）

想跳过识别、直接到位（黑框位置已经量过且垫子/机械臂没挪动）时，用一次性目标：

```bash
python src/yolo_grasp/place_on_frame.py --channel can1 --target-delta-mm 110.6 152.9 -92.2
# 或绝对坐标（TCP 目标，基座系 mm）：
python src/yolo_grasp/place_on_frame.py --channel can1 --target-base-mm 370.2 126.5 213.8
```

它保持当前（固定点）姿态，把 TCP **沿直线**送到该点：`make_path` 生成 301 个直线上的中间点（与直线偏离 0.0 mm）→ `timed_path`/`execute_path` 执行 → 法兰 3 mm / 1° 复核 → 打印到位 TCP 与残差 → 进入保持（`home`/`quit`）。不加载相机、不做识别。2026-09-11 实测值：黑框中心基座 `(370.2, 126.5, 163.8) mm`（5 组标准差 ≤2 mm），其上方 50 mm 即 `(370.2, 126.5, 213.8) mm`，相对固定点 TCP `(259.6, −26.5, 306.0) mm` 的位移 `(+110.6, +152.9, −92.2) mm`、总长 210.1 mm；对应关节变化 `[+36.2, +33.9, −6.4, −59.2, −4.8, +79.0]°`。

速度用 `--path-speed-deg-s`（默认 2，上限 8）：这条路径的弧长约 79°，2°/s≈74 s、4°/s≈37 s、6°/s≈25 s、8°/s≈18.5 s。不用固件自己的 `move_j` 是因为它不是关节线性插值——2026-09-11 实测它先钻到目标高度以下 27.7 mm 再绕回来（Z 305.3→186.1→213.9 mm），直线路径不会出现这种下探。防补发（调度抖动）的速率上限现在从路径自身推导，所以任何 `--path-speed-deg-s` 都适用，不会再出现"调度抖动导致目标发送过快"的误报。6°/s 实测会让 J6 落后指令 0.91°（超过 0.8° 跟随误差守卫），所以实际可用速度约 4–5°/s。

默认姿态沿用固定抓取点，而那个姿态的工具轴相对竖直倾斜 53°，所以落点看着是"斜的"。用 `--target-rpy-deg` 指定最终 TCP 姿态（基座系 RPY，度，与 `pose_matrix` 同约定）：**夹爪竖直向下就是 `--target-rpy-deg 0 180 0`**（工具轴 (0,0,−1)）；偏航按夹爪方向需要取 0 / 90 / −90（都验证过可解，最大关节变化分别是 55.5° / 70.2° / 109.8°）。姿态变化会由路径生成器用 slerp 分摊到整条路径上（`make_line_path`），不会出现"第一步巨大姿态跳变"。竖直姿态这条路径反而更省：最大关节变化 55.5°（沿用固定姿态是 79°），4°/s 约 29.9 秒。

注意（两段连起来时）：若爪里已经夹着物块，把工具轴从倾斜转到竖直等于把物块也转了 53°，放置朝向要按物块姿态一起考虑。

末段减速：2026-09-11 16:03 在竖直姿态 4°/s 下跑到 t+28.5 s（全程 29.8 s）时 J5 突然从 −0.25° 掉到 −0.89°，被跟随误差守卫（0.8°）停机——前 28 秒所有轴都 ≤0.25°，是减速末段的收尾抖动。所以一次性目标现在分两段执行：前 90% 用 `--path-speed-deg-s`，最后 10% 用 `--final-speed-deg-s`（默认 1.5°/s）收尾；主体 4°/s + 末段 1.5°/s 这条路径约 35 秒。要更慢更稳可以直接把 `--path-speed-deg-s` 降到 2（约 60 秒）。

跟随误差上限：16:03 与 16:07 两次 4°/s 都在 J5 滞后 **0.89°** 时被 0.8° 守卫停机（其它轴 ≤0.87°），说明 4°/s 已经贴着这条路径的极限。`--follow-error-deg`（默认 0.8，即原审计值，范围 0.3–2）可放宽到 1.0–1.5 让快路径通过；硬界限（2°）、终点停稳与法兰复核都不受影响，放宽的代价是真实堵转会晚一点被发现。抓取腿仍按 0.8° 执行（该参数默认值不变）。

运动包络：16:18 那次用 3°/s 时 J2 被"最近 0.25 s 目标 ±0.3°"的运动包络拦住（3°/s 下包络尾沿比跟随误差更早触发）。`--motion-envelope-deg`（默认 0.3，即原审计值，范围 0.1–2）可放宽到 0.6–1.0。

**这些"滞后"其实是关节帧的假象，不是手臂跟不上**：16:28 的 2°/s 运行里，失败前 J2 反馈在**一个采样内从 61.461° 倒退到 60.740°（−0.721°）并保持**，而当时指令是平滑的（2°/s、每采样约 +0.02°）。12 ms 内物理倒退 0.72° 不可能，属于与 J6 零点区锁死同类别的上报故障。4°/s 的 J5 1.26°、3°/s 的 J2 0.84° 也是这种跳变。因此放置腿现在也启用双通道记录（`grasp/can_trace.py`），任何停止都会写 `can_trace_abort.jsonl`，可直接用电机通道核对是真是假。要让这些毛刺不再停机，把 `--motion-envelope-deg` 与 `--follow-error-deg` 一起放宽到毛刺量级之上（例如 1.0 / 1.5），硬界限 2° 仍是单帧立即停。

2026-09-14 更新：**默认不再预移动**——`--pre-shift-mm` 默认改成 `0 0 0`，流程就是"到固定抓取点 → 直接在固定点识别黑框 → `go` 接近"，终端不会再出现 `shift` 提示（现场现在固定点就能看全垫子）。需要时仍可用 `--pre-shift-mm 0 80 0` 打开这一步（2026-09-11 实测的"向右"方向，任意 (SX,SY,SZ)，每个 ≤ ±200 mm）；带非零值时终端才会提示 `输入 shift 回车：TCP 在基座系预移动 [SX, SY, SZ] mm 后开始识别`，输入 `shift` 才移动，`quit` 在该提示处直接退出、不发送目标。

## 完整抓放：两条腿串成一个会话（`pick_and_place.py`，2026-09-14）

入口 `python src/yolo_grasp/pick_and_place.py --channel can1 --min-available-mb 1200`。

  阶段 1 异常结束（返回非 0 且不是继续码）时组合入口也不会进入放置阶段。
- **放置腿接近时仍实时识别黑框（2026-09-18）**：路径只按固定抓取点规划一次，黑框位置不动，

  能到的高度有限），或让我加"松爪前先降到指定高度"的选项。

## 水平残余：基座系目标微调

TCP 方向（假定法兰局部 +Z）和手眼外参都未完成标定，所以即使高度对上了，终点还会残留一个水平偏差。2026-09-11 现场实测：TCP 距离 80 mm、目标物块上方 35 mm 时高度合适，但抓取点仍偏在物块前方约 5 mm。

新增 `--target-offset-mm DX DY DZ`（基座系毫米，默认 `0 0 0`，每个不超过 ±50）：它在计算上方目标时把目标整体平移，只改位置、不改姿态，也不影响高度。抓取点偏到物块 +X 前方 5 mm 时传 `-5 0 0` 就把它退回来。生效时启动会打印「目标微调(基座系)：…」，并记进 `diagnostic.json` 的 `target_offset_mm` 与 `assumptions`。

注意这是**经验修正**：它按当前这个固定姿态标定，换姿态/换工具就不成立；它也不能替代 TCP 标定（法兰→夹持中心的三维向量）和横向偏移标定。现场每调一次都要重新观测实际落点，不要只看程序打印的 ΔX/ΔY/ΔZ——那个值用的是同一套假设，只能证明"在假设成立的前提下到位"。

也可以直接从工具侧修正：`--tcp-offset-mm TX TY TZ`（法兰系毫米，默认 `0 0 80`；横向每个 ≤ ±50 mm，轴向必须 (0,200]）。它替换 `T_flange_tcp` 的平移分量，横向分量就表示"夹持中心不在法兰 +Z 轴上"。在固定姿态下，法兰系横向偏移与基座系 `--target-offset-mm` 产生同样的位移，区别只是参考系，以及分别记在 `diagnostic.json` 的 `tcp_offset_mm` / `target_offset_mm`。

**一次性量出真实偏移（推荐）**：不要反复猜，用一次接触测量换掉假设。

1. 用 `python src/yolo_grasp/audit_can_trace.py --channel can1 --seconds 180 --output src/yolo_grasp/runs/tcp_probe.jsonl` 开被动录制（只收不发）。
2. 用 `arm_console` 手动 jog，把夹爪的**夹持中心**轻触红块顶面中心，停稳几秒。
3. 把 `tcp_probe.jsonl` 和同一时刻的 `runs/hover_go_*/diagnostic.json` 交给维护者。

需要的量是：录制里 `0x2A2–0x2A4` 解出的法兰位姿（接触时刻）与 `diagnostic.json` 里的 `red_block_base_xyz_m`。真实偏移 = `R_flange^T · (夹持点 − 法兰位置)`，写进 `--tcp-offset-mm` 即可。这样得到的横向分量是实测值，而不是把 X 方向的误差硬对掉。

## 闭合夹爪并抬升（`--grasp`）

加 `--grasp` 后，到达物块上方后不再只是保持，而是（抬升量二选一：`--lift-mm` 给相对抬升量，`--lift-to-mm` 给"最终停在物块上方多少毫米"，默认 `--lift-to-mm 100`，且必须大于 `--clearance-mm`）：

1. **慢慢闭合夹爪**：默认 1 mm 一步、每步 200 ms（≈5 mm/s），用 `--grip-step-mm`（0.2–5）和 `--grip-step-ms`（50–1000）调节；力参数用 `--grip-force-n`（**默认 2 N**，(0,50] N，必须是你现场验证过的值；2026-09-11 用 1 N 时带物块运动抖动略大，判断与夹持偏松、物块在爪内晃动有关，故默认调到 2 N）。每一步都记 `gripper_step` 事件（目标开度、实际开度、力），终端每 0.5 秒打印一行进度。注意：夹爪满行程约 100 mm，2026-09-11 13:31 那次用 0.5 mm/0.35 s（≈1.4 mm/s）+12 s 上限，只从 99.4 mm 闭到 83.2 mm 就超时，所以默认节拍和 45 s 上限都已调整。
2. **判定"夹住"**：实际开度连续 0.7 s 跟不上指令（变化 <0.15 mm）即认为已夹到物块闭不动，随后保持该目标 0.3 s 且开度不变才算确认。开度一直降到 3 mm 说明夹爪之间没有物块，直接报错、**不抬升**；反馈过期/故障/超时（12 s）同样不抬升。
3. **沿基座 +Z 抬升**：用与接近段相同的 `make_path`/`timed_path`/`execute_path`（5°/s、单步 ≤0.5°、同样的守卫与终点复核），把法兰目标沿基座 +Z 平移（`--lift-mm` 相对量，或 `--lift-to-mm − --clearance-mm`），姿态不变。
4. **抬升后复核**：法兰误差 ≤3 mm / 1°，并且夹爪开度相对夹住时变化 ≤0.5 mm（否则判定物块滑脱，报错并停）。

现场参数（2026-09-18 现场确认，已固化进 `run_grasp.sh`、两处默认值和 `README.md`）：`--clearance-mm 15`、`--tracking-lock-height-mm 45`、`--target-offset-mm -43 -28 0`、`--lift-to-mm 100`（相对抬升 85 mm）、`--grip-force-n 2`、`--target-move-mm 50`、`--max-replans 5`、90°/200 mm 包络、`--device cpu --imgsz 320 --min-available-mb 1200`。调整过程：夹取高度 35 → 25 → 15 → 回 25 → 20 → 15；基础补偿随顶面参考改为 `[-43, -28, 0]`，第二轮起的额外补偿仍是 `[+12, +10, 0]`，**第二轮及其后的每一轮重规划都沿用**，即第二轮起总补偿 `[-31, -18, 0]`；Z 保持 0，保证最终高度严格等于 `--clearance-mm`。

**高度参考改为物块顶面（2026-09-18）**：视觉子进程的 `locate_top_surface` 没有机器人位姿，过去只按"离相机最近的那一面"取质心；斜视时 YOLO 框里同时有顶面、朝向相机的侧面和台面，质心被拉低约 1–2 mm，还随视角滑动（2026-09-17 静止物块四站位审计：参考点最大漂移 25.2 mm，其中 Z −0.1 → −8.3 mm）。现在子进程每帧附带 192 点的 ROI 采样（`surface_samples_xyz_m`，按深度均匀抽样），主进程用当前 `T_base_camera` 取**基座 Z 最高的 85% 分位带（±3 mm，≥12 点）的质心**当参考点，即 `TCP = 顶面参考 + [DX, DY, clearance]`。这个顶面修正只在把参考抬高 0.5–45 mm 时生效（块高 20–30 mm；超过 45 mm 视为框里混进了物块上方的其它物体，退回中心像素参考），采样不足或只有中心像素检测（`locate`，例如放置腿）时行为也不变。规划时终端会打印「高度参考：顶面候选（N 点，比中心像素高 +X.X mm）」，`tracking_target_stable` / `handeye_drift_station` 事件带 `height_reference` 字段。注意顶面参考的 X/Y 与旧的中心像素不同（2026-09-18 现场 13 帧：X +2.5…+5.6 mm、Y −4.0…+2.9 mm、Z +1.2…+2.4 mm），`--target-offset-mm` 的 X/Y 要按这个差值复核一次。

夹爪反馈走独立的、只收不发的 SocketCAN 监听（`grasp/gripper.py`，订阅 `0x2A8`），不参与机械臂状态解码；反馈缺失或监听启动失败时**拒绝闭合夹爪**。监听刚启动、效应器刚初始化时第一帧可能还没到（2026-09-11 13:44 就在闭合请求后 0.00 秒报 `缺少夹爪反馈`），所以闭合前会先**等第一帧有效反馈（最多 3 s）**并打印当前开度。不加 `--grasp` 时入口仍然完全不发送夹爪指令，行为与以前一致。

现场前提：夹爪力必须按真实硬件规格设定（不能把通信编码上限当作允许力），物块不能被压坏，指爪与台面、物块无干涉，抬升路径（上方 30 mm）清空且有人可随时急停（空格/Esc/Ctrl+C）。抬升后物块只靠夹持力保持，程序不会自动松开或放下。

## `home` 改为两段返回

到位保持里输入 `home` 不再从悬停点直接跳回初始位置：**先回固定抓取点 `[-5, 56.138, -52.908, -2, 38.796, -0.902]°`（即 `TARGET_DEG`），停稳并确认误差 ≤0.2° 后，再回 `local/arm_home.json` 保存的初始位置**，两段都打印每个关节需要移动的角度并按 0.2° 复核。已经停在固定抓取点时第一段自动跳过。这样做的原因是 2026-09-11 10:46 的实测：从悬停点直接回初始位置是单条大行程 SDK 目标（每轴最多约 90°），J5 真实越过目标 2.5°（关节帧与电机帧双通道一致），被硬界限拦停。
